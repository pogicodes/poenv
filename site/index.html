poenv

Your configs and secrets in one encrypted vault on your machine. Switch a repo's .env between environments with one command, and let AI agents use your secrets without poenv ever showing them the values.

cd my-app
poenv init                 # import the env file into the vault
poenv use staging          # the env file is now on staging
poenv add OPENAI_API_KEY   # pull in a key you share across apps
poenv run -- npm test     # inject the env without writing a file
One local vaultA single AES-256-GCM file, opened by a key from your recovery phrase. No password to type, the same on macOS, Linux and Windows. No server, no account.
Whole-folder switchingpoenv use staging rewrites the env file itself, so Next.js, Vite, Prisma, Docker Compose and Python all see the new env without wrappers.
Shared keysSet OPENAI_API_KEY once, reference it from every app, rotate it in one place.
Agent-safeAgents can list key names, switch envs and run commands, but poenv never prints a value to them, and they can't touch prod.

Install

macOS & Linux
curl -fsSL https://poenv.pogi.codes/install.sh | sh
Windows (PowerShell)
irm https://poenv.pogi.codes/install.ps1 | iex

No sudo or admin rights. Installs to ~/.local/bin (Windows: %LOCALAPPDATA%\poenv\bin), checks the SHA-256 and adds that folder to your PATH.

Installer options

install.sh flagEnv var (both installers)Does
--version XPOENV_VERSIONInstall a specific release
--dir PATHPOENV_INSTALL_DIRInstall somewhere else
--no-modify-pathPOENV_NO_MODIFY_PATHLeave your PATH alone
--yesDon't ask anything (for agents and scripts)

Pass flags through sh -s --:

curl -fsSL https://poenv.pogi.codes/install.sh | sh -s -- --version 0.0.2

On Windows, set the env vars before running the installer. You can also download a binary from Releases (macOS, Linux and Windows, x64 and arm64).

Update

Run the installer again. It replaces the binary and leaves your vault, PATH and repos alone. poenv --version shows what you have; --version X pins or rolls back.

Uninstall

  1. Delete the binary: rm ~/.local/bin/poenv (Windows: %LOCALAPPDATA%\poenv\bin\poenv.exe).
  2. Remove the line ending in # added by poenv installer from your shell rc file (Windows: remove the folder from your user Path).
  3. Optional and permanent: delete the vault in ~/.poenv (Windows: %APPDATA%\poenv). Run poenv backup first if you might want your secrets back.

Repos keep working: each env file still holds the env it was last switched to. Delete .poenv and the poenv section in AGENTS.md if you like.

Quick start

  1. Check your setup. 
    poenv doctor
    It checks PATH, the vault and the current repo, and prints the exact command for anything to fix.
  2. Set up a repo. 
    cd your-repo
poenv init
    The first time on a machine, init creates your vault and shows a 24-word recovery phrase, once. Save it in your password manager: it opens your backups, and rebuilds this machine's key if it's ever lost. There's no password: poenv opens the vault on its own.

    init then imports your existing env file into the local env, creates staging and prod (protected), writes .poenv, gitignores it and the env file, and adds poenv notes to AGENTS.md or CLAUDE.md.

  3. Fill in another env and switch to it. 
    poenv set DATABASE_URL --env staging   # asks for the value, hidden
poenv use staging
    Or paste KEY=VALUE lines into the env file and run poenv import --env staging, or run poenv on its own to edit everything in the TUI.

Concepts

TermMeans
VaultOne encrypted file on your machine holding every app, env and key. App names and key names are encrypted too, not only values.
AppOne per repo, e.g. my-app. Named in the repo's .poenv file.
EnvA set of keys for an app: local, staging, prod, or any name you add. An env can be protected.
KeyA name and a value. Every change keeps the previous value: the last 10 versions per key.
Shared keyA key that belongs to no app, like OPENAI_API_KEY. Apps hold a live reference to it, optionally under another name.
Managed blockThe section at the top of the env file that poenv writes. Everything outside it is yours.

Switching envs

poenv use staging
✓ my-app: local → staging  (.env.local)
  ~ DATABASE_URL
  ~ STRIPE_SECRET_KEY
  + SENTRY_DSN

poenv rewrites the managed block of the repo's env file and lists what changed, by key name only. With no argument, poenv use opens a picker. Running apps need a restart unless they reload .env themselves.

Manage envs

poenv env new preview --from staging   # copy an env (or omit --from for an empty one)
poenv env rename preview qa            # the env file and .poenv follow
poenv ls                               # apps, envs and key names

Show the env in your prompt

poenv status --short prints my-app:staging. It never opens the vault, so it's instant and safe to run on every prompt.

Shared keys

Keys you use in many apps, like an API key, belong in the shared pool. Set it once, then reference it from each app:

poenv set OPENAI_API_KEY --shared              # once
poenv add OPENAI_API_KEY                       # in each repo: a live reference
poenv add OPENAI_API_KEY --as NEXT_PUBLIC_OPENAI_KEY   # under another name

Rotating it with poenv set OPENAI_API_KEY --shared rewrites the env file of every repo on this machine that uses it, and lists those files.

To copy a value once instead, with no link, take it from another app: poenv add STRIPE_KEY --from other-app/staging.

When init finds a key with the same name and value in another app, it offers to move it into the shared pool and turn each copy into a reference.

Removing a shared key

poenv never leaves dangling references. If apps still use the key, choose:

  • poenv rm KEY --shared --keep-copies: each app keeps its own copy, with history. This is how you undo sharing.
  • poenv rm KEY --shared --everywhere: the references go too.

Protected envs

prod is protected from the start. Switching to a protected env, running with it, or copying or renaming it asks a person to type a confirmation. Agents and scripts are refused with exit 4, and --yes doesn't skip it. Toggle protection on any env with P in the TUI.

Running without a file

poenv run -- npm test                 # the current env
poenv run staging -- npm run migrate  # another env

poenv run injects the env as variables into one command and leaves the env file alone. Nothing is written to disk and no quoting applies, so use it for tools that don't read .env, for values a loader can't parse, or when you'd rather not have secrets in a file at all. It passes through the command's output and exit code. Anything after --, including --json, belongs to your command.

Frameworks & formats

poenv works with anything that reads a .env-style file. init picks the file and quoting format from the repo:

RepoFileFormat
Next.js (next in package.json).env.localnext
Python (pyproject.toml, requirements.txt or Pipfile).envpython
Anything else: Vite, Remix, Express, Bun, Docker Compose….envdotenv

If the repo's env files already hold keys, init uses the file that has them (and asks when several do). Override with --file and --format, or edit .poenv.

The format only matters for values containing $ or escapes, which loaders read differently. Each format is checked in CI against the real Node dotenv, Next.js, Expo, python-dotenv, java.util.Properties and Spring Boot loaders.

Vite and Bun expand $VAR in env files, so they'd read the dotenv format's unescaped $ as a variable. Use --format next there, which escapes it as \$.

A few values can't be written exactly in some formats (for example ${…} for python). poenv writes them as best it can, lists the keys, and suggests poenv run.

Java & Spring Boot

Spring Boot doesn't read .env files, so poenv use alone changes nothing for it. Inject the env with poenv run:

poenv run -- ./mvnw spring-boot:run
poenv run staging -- ./gradlew bootRun

Spring reads environment variables natively: reference them in application.properties (spring.datasource.password=${DB_PASSWORD}), or name keys for relaxed binding (SPRING_DATASOURCE_URL sets spring.datasource.url).

With Docker Compose, env_file: .env reads the file poenv writes. Avoid spring.config.import=optional:file:.env[.properties]: properties files don't strip quotes, so any value poenv quotes keeps its quotes.

CI & servers

poenv opens the vault without a prompt, so scripts and CI work as long as the vault is on the machine. To put it on a server, copy the vault folder (store.enc and keys.json), or run poenv restore there once in a terminal (it asks for your recovery phrase).

Set POENV_HOME to keep the vault somewhere other than the default folder.

Backup & recovery

poenv backup backup.enc    # encrypted copy of the vault
poenv restore backup.enc   # restore it, on this machine or another

A backup plus your recovery phrase restores everything on any machine: on a new machine, restore asks for the phrase. Restoring over an existing vault asks first and keeps the old one as store.enc.bak-<time>.

SituationRun
This machine lost its key (keys.json)poenv recover: type the phrase
Check the phrase you saved is rightpoenv recover --check
Phrase may have leakedpoenv recover --new-phrase (older backups still need the old phrase)
Undo a bad change to a keypoenv history KEY, then poenv rollback KEY [N]

Lose both this machine's key and the phrase, and the vault can't be opened. Nobody can reset it for you.

Stable, so scripts and agents can act on them. Errors always say the command that fixes them.

The env file

poenv owns one block at the top of the env file and never touches anything else (except during init and import, which move the keys they import into the block):

# >>> poenv >>> (managed: edits here are overwritten)
# app: my-app  env: staging
DATABASE_URL=postgres://staging-db/app
OPENAI_API_KEY='sk-…'
# <<< poenv <<<

DEBUG=true   # yours: kept as-is, and it wins over the block

Because the block is at the top, your own lines below it override it in every loader. A key set in both places is reported as a conflict.

A change made anywhere (set, add, rm, rollback, or the TUI) also rewrites the block in every other repo on this machine whose current env it affects. Each repo stays on its own env.

The .poenv file

Written by init at the repo root. It holds names only, never secrets.

app    = "my-app"
env    = "local"        # the env the file is on
file   = ".env.local"   # the env file poenv writes
format = "next"         # dotenv | next | python | properties

It's gitignored by default. You can commit it instead: a teammate's poenv init in a fresh clone then adopts its settings, and poenv leaves a tracked .poenv alone.

For AI agents

Agents can do the daily work: check status, list key names, switch envs and run commands with secrets injected. poenv never prints a value to them, never accepts one as an argument, and keeps values out of --json.

poenv status --json              # which app/env this repo is on
poenv ls --json                  # envs and key names, never values
poenv use staging --json         # switch the env file
poenv run staging -- npm test    # run with an env injected
poenv doctor --json              # when something is off: follow each "fix"

Agents are refused (exit 4) for get, history, rollback, backup, restore, recover and protected envs, and can't create the vault (exit 5), since that shows the recovery phrase.

poenv init adds a short section to AGENTS.md / CLAUDE.md telling agents these rules. To have an agent install poenv, point it at llms.txt or the agent install guide, or say:

Install poenv (https://poenv.pogi.codes/llms.txt) and set up this repo.

The /poenv skill

Install the poenv agent skill once and every coding agent on your machine knows these rules in any repo: Claude Code, Codex, Cursor, Gemini CLI, GitHub Copilot, OpenCode and more.

npx skills@1.7.6 add pogicodes/poenv-skill

Then type /poenv setup or /poenv use staging ($poenv in Codex). Agents also reach for it on their own when you ask about env vars.

How poenv tells people from agents

A person has an interactive terminal on stdin and stdout and none of the markers coding agents set (CLAUDECODE, CODEX_SANDBOX, CURSOR_AGENT, GEMINI_CLI, AI_AGENT, …). A CI variable counts as a script too.

Security model

  • The vault's key sits next to it in keys.json (owner-only), so there's no password to type. Programs running as you, agents included, can read it.
  • Encryption protects the vault file and poenv backup files when copied on their own: they open only with your recovery phrase. A copy of the whole vault folder holds the key too, so encrypt your OS backups.
  • Values are never printed by agent-usable commands, never accepted as arguments (so they stay out of shell history), and never in --json output.
  • Once a value is written to an env file, anything that can read that file can read it, and a command run with secrets injected can print them. poenv run avoids writing files at all.

These rules keep secrets out of poenv's own output. They are not a sandbox: an agent that can read your files can read a written .env.

Troubleshooting

Start with poenv doctor. It checks PATH, the vault, your saved phrase, gitignore, agent notes, dangling shared references and whether the env file is up to date, and names the fix for each. poenv doctor --fix applies the safe ones; it never runs sudo.

poenv: command not found after installing

Open a new terminal so the PATH change applies, or use the full path the installer printed.

My app still sees the old values

Restart it: most dev servers read .env only at startup. Also check you don't set the same key below the poenv block, since your lines win.

A value with $ comes out wrong

Your loader expands variables. Switch the format (--format next escapes $), or use poenv run. See Frameworks & formats.

An agent keeps getting exit 5

The vault doesn't exist yet, or this machine lost its key. Run the first poenv init (or poenv recover) in your own terminal. Never give the agent your recovery phrase.
